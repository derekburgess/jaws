## Context

Describe the forces that require a decision, the constraints that already apply,
and why leaving the choice implicit would be harmful. Distinguish observed facts
from assumptions.

## Decision

State the decision directly. Define its scope, invariants, and any implementation
details intentionally left open for a later ADR.

## Alternatives considered

### Alternative name

Describe the alternative and why it was not selected. Include credible benefits,
not only disadvantages.

## Consequences

### Benefits

- List the expected benefits.

### Costs and limitations

- List complexity, constraints, operational costs, and risks introduced by the
  decision.

### Follow-on constraints

- List rules that later implementations and decisions must respect.

## Benchmark impact

Explain how the decision affects Benchmark 0, later benchmarks, parity checks,
metrics, datasets, expected failures, or reproducibility evidence. State
explicitly when there is no analytical impact.

## Migration

Describe how the current implementation and stored data move toward the decision,
including compatibility boundaries and rollback needs. Name the milestone that
owns the work when known.

## Reversal conditions

Describe evidence that would justify revisiting the decision and what would be
required to reverse it safely. A reversal of an accepted ADR requires a
superseding ADR.

## References

- Link supporting project documents, code, experiments, or external sources.
